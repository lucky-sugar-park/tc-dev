# 가상 PLC 사용 안내 — 종류별 설명

> 작성일: 2026-11-01 (v0.4.0). 대상: `wow-tc-backend/vplc`, tc 화면 **가상 PLC › 가상 PLC 목록 / 메모리 보기·제어**.
> 설계와 결정은 [virtual-devices.md](virtual-devices.md), REST 표도 그쪽에 있다. 이 문서는 "무엇이고, 어떻게 쓰는가"를 종류별로 풀어 쓴다.

## 1. 가상 PLC 가 무엇인가

tc 는 공장의 PLC 와 통신하는 게이트웨이다. 개발·시험 때마다 진짜 PLC 를 붙일 수는 없으므로, **PLC 인 척 답하는 프로그램**을 대신 둔다. 이것이 가상 PLC 다.

- **vplc** 는 그런 가상 PLC 들을 띄우는 앱 하나다(기본 REST 포트 8088).
- vplc 안에는 **세 종류**의 가상 PLC 를 **여러 대씩** 둘 수 있다 — MELSEC MC, Modbus TCP, OPC UA. tc 의 커넥터 프로토콜과 하나씩 짝이 된다.
- 세 종류 모두 vplc DB 의 같은 표(VPLC)에 등록되고, 같은 순서로 켜고 끈다. 화면도 같은 목록·같은 작업 메뉴를 쓴다.

```
 tc (커넥터)                         vplc 앱 하나
 ─────────────                       ───────────────────────────────────────────
 MELSEC_MC 커넥터  ── MC 3E/4E ──▶   MELSEC 가상 PLC  (예: vplc-e2e  :15000)
 MODBUS_TCP 커넥터 ── Modbus TCP ─▶  Modbus 가상 PLC  (예: mb-e2e    :15020 단위 1)
                                     Modbus 가상 PLC  (예: mb-e2e-2  :15020 단위 2)
 OPC_UA 커넥터     ── OPC UA ─────▶  OPC UA 가상 PLC  (예: ua-e2e    :4840/vplc)
```

## 2. 모든 종류에 같은 것 — 상태 단계

가상 PLC 는 다음 단계를 거친다. 종류와 관계없이 같다.

| 상태 | 뜻 | 할 수 있는 일 |
|---|---|---|
| **REGISTERED** | DB 에 정의만 있다. 메모리에 없고 포트도 닫혀 있다 | 수정, 게시, 삭제 |
| **PUBLISHED** | 메모리에 올렸다(값을 담을 그릇이 생김). 포트는 아직 닫혀 있다 | 시작, 메모리 보기, 해제 |
| **RUNNING** | 포트를 열고 요청에 답한다 | 일시정지, 정지, 연결 끊기, 메모리 보기·바꾸기 |
| **PAUSED** | 연결은 그대로 두고 **답하지 않는다** — tc 시간 초과 시험용 | 재개, 정지 |
| **STOPPED** | 포트를 닫았다. 메모리 값은 남아 있다 | 시작, 해제 |
| **RELEASED** | 메모리에서 내렸다(값도 사라짐) | 게시, 삭제 |

- **게시 → 시작** 두 번을 거쳐야 tc 가 붙을 수 있다. 목록에서 줄이 흐리면 게시되지 않은 것이다.
- vplc 를 다시 띄우면 게시·실행 중이던 것은 다시 올라오고, **RUNNING 이던 것은 바로 시작**한다.
- 메모리 값(레지스터·태그의 지금 값)은 vplc 를 다시 띄우거나 해제하면 처음으로 돌아간다. 정의(이름·포트·설정·OPC UA 태그 목록)는 DB 에 남는다.
- **연결 클라이언트 보기**(목록의 ⋮ 메뉴, 또는 **연결 수** 칸을 누름)는 포트마다 연결 수와 지금 붙은 클라이언트 IP 를 가로 표로 보인다(마우스를 올리면 연결된 때·채널). 붙고 끊긴 기록은 **가상 PLC › 가상 PLC 연결 이력** 화면에서 찾는다. **연결 끊기**는 붙은 연결을 모두 끊는다 — 포트는 계속 열려 있어 tc 가 다시 붙는지(재연결) 시험할 때 쓴다.
- **포트당 연결**은 한 포트에 동시에 붙을 수 있는 수다. 넘으면 새 연결을 바로 닫는다.

## 3. MELSEC MC 가상 PLC

미쓰비시 PLC 의 MC 프로토콜(3E·4E 프레임)에 답한다. tc 의 `MELSEC_MC` 커넥터 상대.

**등록 칸**

| 칸 | 뜻 | 예 |
|---|---|---|
| 프레임 | BINARY 또는 ASCII — tc 커넥터의 프레임 설정과 같아야 한다 | BINARY |
| IP · 시작 포트 · 포트 수 | 시작 포트부터 포트 수만큼 연다(한 PLC 가 포트 여러 개) | 127.0.0.1 · 15000 · 1 |
| 포트당 연결 | 진짜 PLC 는 보통 1 | 1 |
| 메모리 종류 | 만들 디바이스 — D·W·R·ZR(워드), M·L·B·X·Y·F·V·S·SM(비트) 등. 만들지 않은 디바이스를 읽으면 MC 오류 코드로 답한다 | D, M |

**메모리 보기·제어**

- 메모리 종류·시작 주소·워드 수로 표를 본다. 주소 표기는 MELSEC 그대로(D100, W1A0 — W·B·X·Y 는 16진).
- 한 줄 = 한 워드. 10진·부호 없음·16진·비트 16개·ASCII 를 함께 보인다. 비트 디바이스(M 등)는 비트마다 주소가 붙는다.
- 10진 칸을 고쳐 쓰거나, 비트를 눌러 켜고 끄거나, **값 쓰기**로 여러 값(쉼표, `0x` 16진)·문자열을 쓴다. 문자열은 **한 워드에 두 글자, 낮은 바이트가 앞 글자**(MC 와 같다) — "AB" 는 `4241`.
- **모두 지우기**는 그 메모리 종류 전체를 0 으로.

**tc 쪽 짝 맞추기** — 커넥터 프로토콜 `MELSEC_MC`, 호스트·포트 = 가상 PLC 의 IP·포트, 프레임 같게. 점 주소는 `D100`, `M10`, 워드 안 비트 `D100.A`(docs/word-bit-points.md).

## 4. Modbus TCP 가상 PLC

Modbus TCP(MBAP + PDU)에 답하는 장치다. tc 의 `MODBUS_TCP` 커넥터 상대.

**한 대 = 포트 + 단위 ID.** Modbus 는 요청마다 단위 ID(Unit ID)를 싣는다. 게이트웨이 하나(포트 하나) 뒤에 장치가 여러 대 있으면 단위 ID 로 구분한다. vplc 에서는 **같은 포트에 단위 ID 가 다른 가상 PLC 를 여러 대 등록**해 이것을 흉내 낸다.

- 같은 포트의 첫 장치가 시작하면 포트를 열고, 마지막 장치가 정지하면 닫는다.
- 그 포트에 실행 중이 아닌 단위 ID 로 요청이 오면 **게이트웨이 예외(0x0B)**로 답한다 — 진짜 게이트웨이와 같다.
- 같은 포트·같은 단위 ID 는 하나만 실행할 수 있다(두 번째는 시작 때 409).

**등록 칸**

| 칸 | 뜻 | 기본 |
|---|---|---|
| IP · 포트 | 포트는 하나 | 127.0.0.1 · (예 15020) |
| 포트당 연결 | 같은 포트의 장치들 중 가장 큰 값이 그 포트의 한도 | 8 |
| 단위 ID | 0~255 | 1 |
| 칸 수 | 네 영역 **각각**의 크기(1~65536) | 10000 |
| 응답 지연(ms) | 요청마다 이만큼 늦게 답한다 — tc 시간 초과 시험. 목록 ⋮ **응답 지연**으로 실행 중에도 바꾼다 | 0 |

**네 영역**

| 영역 | Modbus 이름 | 크기 | tc 주소 | 읽기·쓰기 함수 |
|---|---|---|---|---|
| HR | Holding register | 16비트 | `HR1`… | FC3 읽기, FC6·16 쓰기 |
| IR | Input register | 16비트 | `IR1`… | FC4 읽기(장치 쪽에서만 바뀜) |
| CO | Coil | 비트 | `CO1`… | FC1 읽기, FC5·15 쓰기 |
| DI | Discrete input | 비트 | `DI1`… | FC2 읽기(장치 쪽에서만 바뀜) |

- **번호 주의** — 메모리 화면과 vplc REST 는 **프로토콜 주소(0부터)**를 쓴다. tc 커넥터의 주소 기준(addressBase)이 1(기본)이면 **tc 의 `HR1` = 화면의 `HR0`**. 화면에도 이 안내가 나온다.
- 입력 영역(IR·DI)은 Modbus 클라이언트가 쓸 수 없지만, 장비 쪽 값을 흉내 내려고 **메모리 화면에서는 바꿀 수 있다**.
- 실제 장치와 같은 한도로 답한다 — 한 번에 읽기 비트 2000·레지스터 125, 쓰기 비트 1968·레지스터 123. 넘거나 범위 밖이면 Modbus 예외 코드(02·03)로.

**메모리 보기·제어**

- 레지스터(HR·IR)는 MELSEC 처럼 한 줄 = 한 레지스터.
- 비트 영역(CO·DI)은 **16개를 한 줄로 묶어** 보인다 — 줄 이름은 그 줄의 첫 비트(CO0, CO16, …), 비트마다 툴팁에 번호. 영역 끝에서 자른다(칸 1000 이면 CO999 까지).
- 문자열은 **한 레지스터에 두 글자, 높은 바이트가 앞 글자**(Modbus 에서 흔한 순서) — "AB" 는 `4142`. MELSEC 과 반대다.
- 모두 지우기는 그 영역 전체를 0(false) 으로.

**일시정지** — 그 단위 ID 만 답하지 않는다. 같은 포트의 다른 단위 ID 는 계속 답한다.

**연결 수** — 포트 단위로 센다. `mb-e2e`·`mb-e2e-2` 처럼 같은 포트를 쓰면 같은 연결이 둘 다에 보인다.

**tc 쪽 짝 맞추기** — 커넥터 프로토콜 `MODBUS_TCP`, 호스트·포트 = 가상 PLC 의 IP·포트, 설정 `unitId` = 단위 ID. 같은 커넥터로 다른 단위 ID 를 읽으려면 인터페이스 settings `unitId` 로 덮어쓴다.

## 5. OPC UA 가상 PLC

OPC UA 서버다(Eclipse Milo). tc 의 `OPC_UA` 커넥터 상대.

**한 대 = 엔드포인트 하나** — `opc.tcp://<IP>:<포트><경로>`(예 `opc.tcp://127.0.0.1:4840/vplc`). MELSEC·Modbus 의 "메모리 영역" 대신 **태그(변수 노드)**가 있다.

**등록 칸**

| 칸 | 뜻 | 기본 |
|---|---|---|
| IP · 포트 | 서버가 여는 주소 | 127.0.0.1 · (예 4840) |
| 엔드포인트 경로 | 주소 뒤 경로 | /vplc |
| 로그인 필요 | 켜면 익명 접속을 거절하고 사용자 이름만 받는다 | 끔 |
| 클라이언트 인증서 모두 믿기 | 켜면 보안 연결 때 tc 의 클라이언트 인증서를 따로 믿게 하지 않아도 된다 | 켬 |

- 엔드포인트는 보안 없음(None)과 Basic256Sha256(Sign·SignAndEncrypt)을 모두 열고, 각각 익명·사용자 이름 로그인을 받는다.
- 로그인 사용자는 vplc 설정 `vplc.opcua.users` — 모든 OPC UA 가상 PLC 가 함께 쓴다. 기본 사용자 `tc-e2e`, 비밀번호는 환경 변수 `VPLC_OPCUA_PASSWORD`(없으면 시험용 기본값).
- **서버 인증서는 시작할 때마다 새로 만든다.** tc 커넥터가 "처음 본 서버 인증서를 믿기(TOFU)"로 되어 있으면, 가상 PLC 를 정지했다 시작하거나 vplc 를 다시 띄운 뒤 연결이 거절된다. tc 커넥터 화면에서 **서버 인증서 잊기**를 누르면 다시 붙는다.

**태그**

- 태그 경로 `Line1.Temp` → Objects 아래 폴더 `Line1`, 그 안의 변수 `Temp`. 앞부분은 폴더로 만든다.
- NodeId 는 `nsu=urn:wow:tc:vplc-opcua;s=Line1.Temp`. 네임스페이스 번호는 일부러 **3** 이 되게 해 두었다(`ns=2` 를 가정한 코드를 잡으려고) — tc 에는 번호가 바뀌어도 되는 `nsu=` 형태를 쓰는 것이 좋다. tc 인터페이스 폼의 **노드 찾아보기**가 이 형태로 넣어 준다.
- 형: BOOL·INT16·UINT16·INT32·UINT32·INT64·FLOAT32·FLOAT64·STRING(tc 점 형과 같은 이름).
- **값 흉내** — 주기마다 값을 바꾼다. tc 의 구독(SUBSCRIBE) 인터페이스 시험에 쓴다.

| 흉내 | 하는 일 |
|---|---|
| RAMP | 최소에서 최대까지 1씩 올리고 다시 처음부터 |
| SINE | 최소~최대 사이 사인파 |
| TOGGLE | BOOL 을 켜고 끄기 |
| RANDOM | 최소~최대 사이 아무 값 |

- 태그 **정의**(경로·형·처음 값·흉내·설명)는 vplc DB 에 남는다. **지금 값**은 메모리 — 정지했다 시작하면 처음 값으로.
- 흉내 중인 태그 값을 바꿔도 다음 주기에 흉내 값으로 돌아간다.

**메모리 보기·제어(태그 표)**

- 경로·형·값·값 흉내·NodeId·설명. **태그 추가**(경로·형·처음 값·설명·흉내)·지우기는 언제든(게시 전에도), **값 고쳐 쓰기는 실행 중일 때만**.
- 형에 맞지 않는 값(예: INT16 에 70000, BOOL 에 "abc")은 거절한다.

**일시정지** — 연결(세션)은 그대로 두고, 값 읽기·쓰기 요청을 재개될 때까지 붙잡아 둔다(최대 120초). tc 쪽에서는 응답이 오지 않아 시간 초과가 난다. 재개하면 붙잡혀 있던 요청에 답한다.

**연결 이력** — 세션이 열리고 닫힐 때 클라이언트 주소와 세션 아이디를 남긴다. **연결 끊기**는 세션을 모두 닫는다.

**tc 쪽 짝 맞추기** — 커넥터 프로토콜 `OPC_UA`, 호스트·포트 = 가상 PLC 의 IP·포트, 설정 `endpointPath` = 엔드포인트 경로. 보안 시험은 `securityPolicy` BASIC256SHA256 + `authMode` USERNAME(사용자 `tc-e2e`, 비밀번호는 커넥터 비밀번호 칸). docs/opcua-design.md §7.

## 6. 세 종류 한눈에

| | MELSEC MC | Modbus TCP | OPC UA |
|---|---|---|---|
| 한 대 | 포트 여러 개 | 포트 + 단위 ID(한 포트에 여러 대) | 엔드포인트 하나 |
| 값 담는 곳 | 메모리 종류(D·M…) | 영역 HR·IR·CO·DI | 태그 |
| 주소 예 | D100, M10, W1A0 | 화면 HR0 = tc HR1 | nsu=…;s=Line1.Temp |
| 문자열 | 낮은 바이트가 앞 글자 | 높은 바이트가 앞 글자 | STRING 형 태그 |
| 일시정지 | 답하지 않음 | 그 단위 ID 만 답하지 않음 | 값 읽기·쓰기를 붙잡음 |
| 더 있는 것 | 프레임·메모리 종류 고르기 | 응답 지연 | 값 흉내, 로그인·보안 |
| 다시 띄우면 | 메모리 값 처음으로 | 영역 값 처음으로 | 태그 값 처음으로, 서버 인증서 바뀜 |

## 7. 자주 하는 일

- **새 가상 PLC 만들기** — 가상 PLC 목록 › 추가 › 종류를 고르고 칸을 채워 저장 → ⋮ 게시 → 시작(▶). 이제 tc 커넥터를 그 주소로 등록하면 된다.
- **tc 시간 초과 시험** — 실행 중인 가상 PLC 를 일시정지(⏸). Modbus 는 응답 지연을 tc 의 요청 시간 초과보다 크게 두어도 된다.
- **tc 재연결 시험** — ⋮ 연결 끊기. 포트는 열려 있으니 tc 가 다시 붙어야 한다.
- **장비 값 바꿔 보기** — 메모리 보기·제어에서 값을 쓰고 tc 인터페이스 시험 화면으로 읽는다. 반대로 tc 가 쓴 값이 이 화면에 보이는지 본다(자동 새로 고침 1·2·5초).
- **OPC UA 구독 시험** — RAMP·SINE 같은 흉내 태그를 두고 tc 에 SUBSCRIBE 인터페이스를 만든다.

## 8. 시험용 기본 가상 PLC

tc e2e 시험이 쓰는 것들 — 없으면 시험이 스스로 등록·게시·시작한다(`e2e/common.py` `ensure_vplc`). 지우지 않는 것이 좋다.
